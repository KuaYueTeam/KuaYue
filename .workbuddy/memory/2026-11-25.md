## 碰撞箱修正（同日追加）

用户反馈"碰撞箱基本上都有问题"。诊断：89 个新增方块里有 50 个被注册成
`full_shape_directional`，碰撞箱固定为完整 1×1×1；旧版 1.21.1 里几乎每个零件
（`C31BoardShapes` / `M1WashbasinBlock` / `C31FloorBlock` 等）都有独立 VoxelShape。
KuaYue 当前数据驱动**没有任意 AABB 的配置字段**，碰撞箱完全由 factory 的 Java 类决定。

用户确认方案：**语义化重映射，只改资源包 JSON，不动 Java / schema / 测试**。

### 落地（只改 4 个 blocks.json，共 42 处实质变更）
- 满格 `full_shape_directional` 50 → 21（其中 9 个另加 `no_collision`，实际只剩 12 个大件实心）。
- 侧板/端面 → `train_panel` 9 个；带 hinge 的薄侧板 → `train_hinge_panel` 4 个。
- 上半格地板 → `slab` 3 个；下半格地板/车顶/车底设备 → `slab_top` 11 个。
- 车顶与低矮侧板 → `hinge_slab` + `params.is_carport=true` 6 个（碰撞由 y8..16 改为 y0..8）。
- 小凸起件（风扇/通风罩/手轮/吊扇）→ `air_vent` 5 个（box(5,0,5,12,4,12)）。
- `gc220ii_floor_ladder` → `ladder` + `is_meter=true`。
- 9 个无状态的空模型 companion/company 方块 → block 级 `properties.no_collision=true`。
- 门/窗/烟囱保持原专用形状；门 `params.end_y` 保持 1（改 2 会触发 `PanelBlockItem`
  多格放置，可能生成重复 company 方块，而模型本身已经跨 2 格高）。

### 复用结论
- **换 factory 的硬约束**：blockstate variant key 里出现的属性名必须是新 factory
  状态属性集合的子集，否则模型静默丢失。可用组合：
  `facing` → train_panel / slab / slab_top / air_vent / full_shape_directional；
  `facing,hinge` → train_hinge_panel / hinge_slab / train_unopenable_window；
  `facing,hinge,open` → train_door；`facing,open` → train_small_window。
  `ladder` 是 `facing,hinge,open` 超集，所以也能接只有 `facing` 的 blockstate。
- `no_collision` / `no_collission` 由 KasugaLib `JsonPropertyParser` 编译成
  `BlockBehaviour.Properties.noCollission()`，可写在 **block 级** `properties`，
  与 group 级的 `no_occlusion`/`strength`/`map_color` 叠加不冲突。
- `train_panel` 的形状是贴在格边的 1 像素薄板（`TrainPanelShapes.NORTH_AABB` 等），
  `slab` 是 y8..16、`slab_top`/`hinge_slab(is_carport)` 是 y0..8，
  `train_door` 是 3 像素门板且随 open 切换。

## 根据模型生成精确 AABB（同日第二次追加，已覆盖上一节的"不要改源码"约束）

用户新指令："根据模型生成AABB"，并提示 Minecraft 有 `getShape` / `getCollisionShape`
以及三个判定盒 VisibleShape / InteractionShape / CollisionShape；只 Override `getShape`
时三者默认都取 `getShape` 的值。据此改为**允许改 Java**，做精确 AABB。

### 数据生成规则（模型 → AABB）
- 遍历 89 个新增方块的每个 blockstate variant，解析其 model：
  - 标准 JSON 模型：取所有 `elements[].from/to` 的包围盒（像素）。
  - `loader=neoforge:obj`：解析 `.obj` 的 `v` 顶点，**×16** 换算为像素
    （OBJ 1 单位 = 1 方块；顶点常跨格，如 -1.062..2.062）。
  - 零体积 element（平面片，常见于 C31 侧板）必须过滤，否则得到零厚度盒。
- 按 blockstate 的 `y` 旋转变换盒，绕方块中心 (8,8)：
  0° 原样；90° `x'=16-z, z'=x`；180° `x'=16-x, z'=16-z`；270° `x'=z, z'=16-x`。
- 同一 variant 的所有盒合并成**一个** AABB；再 clamp 到 `-16..32` 像素
  （旧版 `C31BoardShapes` 的跨格惯例），避免篷布/甩出门扇产生 ±100 像素的巨型碰撞箱。
- key 规范化为固定顺序 `facing,hinge,open,lit`（无状态变体用 `""`），
  Java 侧按同一顺序从 `BlockState.getValues()` 重建 key。
- 结果：89 方块 / 629 variant / 620 有效盒 / 9 个空模型块 / 约 41KB，
  写入各 `blocks.json` 的 `params.aabb`。

### Java 机制（新增 1 类 + 改 10 个文件）
- 新增 `core/panel/ModelAabbShapes.java`：解析 `params.aabb`、
  运行时按状态查表；**从完整状态键逐级降级到较短前缀**（最后到 `""`），
  用于 blockstate 变体只声明部分属性的情况（如 `gc220ii_floor_ladder` 用 `ladder`，
  运行时多了 `hinge/open`）。值用 `Property.getName(value)`（`Direction`/`DoorHingeSide` 等）。
- `TrainPanelBlock`：加 `modelAabbShapes` 字段、`configureModelAabb()`、
  `modelAabbShape(state)`；`getShape` 优先返回模型 AABB；
  `getCollisionShape` 改为委托 `getShape`（原本两者返回值相同，无行为变化）。
  `getInteractionShape` 由 `BlockBehaviour` 默认委托 `getShape` → **三个判定盒一致**。
- 在 `FullShapeDirectionalBlock`、`SlabBlock`、`HingeSlabBlock`、`TrainDoorBlock`、
  `AirVentBlock`、`LadderBlock` 的 `getShape` 开头加同样的查表（这些子类都 Override 了
  `getShape`，只改父类会被绕过）；它们的 `getCollisionShape` 本来就委托 `getShape`。
- 注入点三处（都持有 params 并刚创建完方块）：`PanelReg`、`SlabReg`、
  `BlockFactories.panelWithDefaultItem`，在 `configureMultiCell` 后调用
  `configureModelAabb(ModelAabbShapes.parse(params))`。
- **其它包无 `aabb` → parse 返回 NONE → 完全走原逻辑**，无回归。
- `doc/schemas/data-driven/v1/content.schema.json`：新增 `$defs/modelAabbParams`，
  给 6 个 params 定义（panelBounds / trainPanelEmpty / trainSmallWindow /
  trainUnopenableWindow / ladder / hingeSlab）加 `aabb` 放行；README 补说明。

### 三个判定盒的坑
KuaYue 的面板子类**自己 Override 了 `getCollisionShape`**，所以"只改 getShape"
在这些类里不会自动影响 CollisionShape；必须让 `getCollisionShape` 委托 `getShape`
（本次已统一）。另外 `no_collision` 对 Override 了 `getCollisionShape` 的方块本就无效，
现在 9 个空模型块由 `aabb: []` → `Shapes.empty()` 直接让三个盒子都空，不再依赖该属性。
