# 数据驱动注册列车方块

## 概述

Kuayue 已支持通过 JSON 配置文件来注册列车方块，**无需编写任何 Java 代码**。只需要写 JSON 文件，放入正确的路径，游戏就会自动读取并生成方块。

数据驱动注册由两部分组成：

- **索引文件**：一份文件清单，只回答"要解析哪些文件"；
- **内容文件**：真正的对象定义（分组、方块），是唯一的事实来源。

一个车型通常一个索引文件，外加 `groups.json` / `blocks.json` 两个内容文件。

## 文件放哪里？

每个车型是一个独立的模块目录（含 `module.toml`），在其下建立索引与内容：

```
modules/train-parts/resources/<类别>/<车型>/
├── module.toml                                    ← 模块标记（已有，勿删）
└── data/kuayue/
    ├── kasuga_lib/data_driven/<名称>.json          ← 索引文件（文件清单）
    └── carriages/<名称>/                            ← 内容文件（对象定义）
        ├── groups.json
        └── blocks.json
```

以 m1 车型为例（`resources/carriages/m1/`）：

```
modules/train-parts/resources/carriages/m1/
├── module.toml
└── data/kuayue/
    ├── kasuga_lib/data_driven/m1.json              ← 索引：{"on_register": ["carriages/m1/groups.json", "carriages/m1/blocks.json"]}
    └── carriages/m1/
        ├── groups.json                             ← 分组定义
        └── blocks.json                             ← 方块定义
```

> **不要**直接改 `modules/train-parts/src/compiled/resources/`——那是资源编译的**生成物**，每次构建都会重新生成并覆盖你的手改。

## JSON 规范

### 索引文件

索引文件是一份**文件清单**，用 `on_register` 字段——一个字符串数组——列出**启动注册**时要解析的内容文件。路径相对 `data/kuayue/`，**必须带 `.json` 后缀**：

```json
{
  "on_register": [
    "carriages/m1/groups.json",
    "carriages/m1/blocks.json"
  ]
}
```

- 索引文件**只认 `on_register` 与 `on_reload`**——旧字段名 `sources` 已不再识别，写 `registry_groups`/`blocks` 等其它顶层字段同样会被拒绝并计入加载错误；
- `on_reload` 与 `on_register` 同形（字符串数组），列出**只在资源重载时**才消费的内容文件；列车方块的注册内容一律写 `on_register`。同一个内容文件不能同时出现在两个字段里，否则两个域都不消费它；
- 索引**不声明类型**，每个内容文件里是什么类型由内容文件自己的顶层字段决定；
- 同一内容文件被多个索引列出时只解析一次。

### 内容文件

内容文件承载真正的数据，顶层字段是注册类型：**分组（registry_groups）** 和 **方块（blocks）**。

`groups.json`：

```json
{
  "registry_groups": [
    {
      "id": "kuayue:my_group",
      "properties": {
        "no_occlusion": true,
        "strength": [1.5, 3.0],
        "map_color": "blue"
      },
      "item_properties": {
        "tab": "kuayue:train_panel_tab"
      }
    }
  ]
}
```

`blocks.json`：

```json
{
  "blocks": [
    { "id": "kuayue:my_block", "type": "slab", "registry_group": "kuayue:my_group" },
    { "id": "kuayue:my_door", "type": "custom_rendered_door", "params": { ... }, "registry_group": "kuayue:my_group" }
  ]
}
```

### 分组（registry_groups）

分组用于给一批方块定义共同的属性，避免重复写。每个分组支持：

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` | 分组 ID，格式 `kuayue:xxx` | 是 |
| `properties` | 方块属性（见下方） | 否 |
| `item_properties` | 物品属性 | 否 |
| `model` | 模型路径覆盖 | 否 |
| `state_machine` | 状态机覆盖 | 否 |
| `block_entity` | 绑定的方块实体 | 否 |

**properties 可用选项：**

| 字段 | 示例值 | 说明 |
|---|---|---|
| `no_occlusion` | `true` | 不遮挡周围方块，穿透渲染 |
| `strength` | `[1.5, 3.0]` | 硬度与爆炸抗性 |
| `map_color` | `"blue"` | 地图颜色 |
| `requires_tool` | `true` | 是否需要工具采收 |
| `sound_type` | `"metal"` | 声音类型 |

**item_properties 可用选项：**

| 字段 | 示例值 | 说明 |
|---|---|---|
| `tab` | `"kuayue:train_panel_tab"` | 所属创造模式标签页 |

### 方块（blocks）

每个方块支持：

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` | 方块 ID，格式 `kuayue:xxx` | 是 |
| `type` | 方块类型（见下方类型清单） | 是 |
| `registry_group` | 所属分组 ID | 是 |
| `params` | 该方块类型的额外参数 | 否 |
| `properties` | 覆盖分组的 properties，只对本方块生效 | 否 |
| `model` | 覆盖分组模型路径 | 否 |
| `state_machine` | 覆盖分组状态机 | 否 |
| `block_entity` | 覆盖分组绑定的方块实体 | 否 |

## 方块类型清单

以下是目前已实现的全部 19 种方块类型。`type` 字段填写对应的类型名：

### 基础面板类

#### `"train_panel"` — 普通面板

车厢侧壁面板，可自由控制碰撞箱范围。

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `begin_x` | float | `0.0` | 碰撞箱 X 起点 (0~1) |
| `begin_y` | float | `0.0` | 碰撞箱 Y 起点 (0~1) |
| `end_x` | float | `1.0` | 碰撞箱 X 终点 (0~1) |
| `end_y` | float | `1.0` | 碰撞箱 Y 终点 (0~1) |

**示例：** 不指定则使用默认 1x1 碰撞箱
```json
{ "id": "kuayue:panel_mid", "type": "train_panel", "registry_group": "..." }
```

#### `"train_hinge_panel"` — 铰链面板

带铰链（折叠边缘）的面板，参数同上。

```json
{ "id": "kuayue:panel_hinge", "type": "train_hinge_panel", "registry_group": "..." }
```

#### `"slab"` — 底板

地板、脚踏板等贴地方块。

```json
{ "id": "kuayue:floor", "type": "slab", "registry_group": "..." }
```

#### `"slab_top"` — 顶板

车顶板、天花板等。

```json
{ "id": "kuayue:carport", "type": "slab_top", "registry_group": "..." }
```

#### `"ladder"` — 梯子

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `is_meter` | boolean | `false` | 是否为米轨车型的梯子 |

```json
{ "id": "kuayue:ladder", "type": "ladder", "registry_group": "..." }
{ "id": "kuayue:ladder_m1", "type": "ladder", "params": { "is_meter": true }, "registry_group": "..." }
```

#### `"air_vent"` — 通风口

```json
{ "id": "kuayue:air_vent", "type": "air_vent", "registry_group": "..." }
```

#### `"skirt"` — 裙板

车厢底部的装饰裙板。

```json
{ "id": "kuayue:skirt", "type": "skirt", "registry_group": "..." }
```

#### `"level_panel"` — 水平面板

水平放置的面板（如车钩区域的面板），可自由控制碰撞箱。

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `begin_x` | float | `0.0` | 碰撞箱 X 起点 |
| `begin_y` | float | `0.0` | 碰撞箱 Y 起点 |
| `end_x` | float | `1.0` | 碰撞箱 X 终点 |
| `end_y` | float | `1.0` | 碰撞箱 Y 终点 |

```json
{ "id": "kuayue:level_panel", "type": "level_panel", "params": { "begin_x": 0.25, "end_x": 0.75 }, "registry_group": "..." }
```

#### `"level_window"` — 水平窗户

```json
{ "id": "kuayue:level_window", "type": "level_window", "registry_group": "..." }
```

#### `"hinge_slab"` — 铰链地板

带有铰链的地板块（通常用于车顶盖板）。

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `is_carport` | boolean | `false` | 是否为车顶板 |
| `width` | int | `1` | 宽度 |

```json
{ "id": "kuayue:floor_battery", "type": "hinge_slab", "params": { "is_carport": true }, "registry_group": "..." }
```

### 窗户类

#### `"train_small_window"` — 小窗户

不可开启的装饰小窗，可设置高度。

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `height` | int | `1` | 方块高度（格子数） |

```json
{ "id": "kuayue:window_small", "type": "train_small_window", "params": { "height": 2 }, "registry_group": "..." }
```

#### `"train_openable_window"` — 可开启窗户

可以开合的窗户，支持多种宽度/范围配置。

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `wide` | int | `1` | 窗户宽度（格子数） |
| `left` | int | `0` | 向左偏移（负数） |
| `right` | int | `1` | 向右偏移（正数） |
| `height` | int | `1` | 高度（格子数） |

> `wide` 和 `left`/`right`/`height` 是两组配置：如果不指定 left/right/height，则按 wide 创建。两个模式二选一即可。

```json
{ "id": "kuayue:window_large", "type": "train_openable_window", "params": { "wide": 2 }, "registry_group": "..." }
{ "id": "kuayue:window_m1", "type": "train_openable_window", "params": { "left": -1, "right": 1, "height": 2 }, "registry_group": "..." }
```

#### `"train_unopenable_small_window"` — 不可开启小窗

密封的小窗户，和普通面板类似。

```json
{ "id": "kuayue:window_sealed", "type": "train_unopenable_small_window", "registry_group": "..." }
```

#### `"train_unopenable_window"` — 不可开启宽窗

密封的宽窗，可控制大小和位置。

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `wide` | int | `1` | 宽度 |
| `begin_y` | int | `0` | Y 方向起点 |
| `end_y` | int | `1` | Y 方向终点 |

```json
{ "id": "kuayue:slab_top_m1", "type": "train_unopenable_window", "params": { "wide": 2, "begin_y": 0, "end_y": 2 }, "registry_group": "..." }
```

### 自定义渲染类

#### `"custom_rendered_door"` — 自定义渲染门

使用自定义模型的列车门，支持上下两段模型。**必须提供 left_models 和 right_models。**

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `left_models` | string 数组 | **必填** | 左门页模型 ID 列表（下段/上段） |
| `right_models` | string 数组 | **必填** | 右门页模型 ID 列表 |
| `offset` | double 数组 | `[0,0,0]` | 位置偏移 `[x, y, z]` |
| `open_offset` | double 数组 | `[0,0,0]` | 开门后偏移 |
| `render_shape` | string | `"entityblock_animated"` | 渲染方式：`"entityblock_animated"` 或 `"model"` |
| `is_slide_door` | boolean | `false` | 是否为滑塞门 |

**left_models / right_models 数组说明：** 门由上下两段模型组成。左页门上下段的模型路径，右页门同理。

```json
{
  "id": "kuayue:door_25t",
  "type": "custom_rendered_door",
  "params": {
    "left_models": ["kuayue:door/original_25t_door_bottom_hinge", "kuayue:door/original_25t_door_top_hinge"],
    "right_models": ["kuayue:door/original_25t_door_bottom", "kuayue:door/original_25t_door_top"]
  },
  "registry_group": "kuayue:c25t_panels"
}
```

滑塞门示例（left 和 right 与普通门相反，且设置 `is_slide_door: true`）：
```json
{
  "id": "kuayue:door_sliding_25t",
  "type": "custom_rendered_door",
  "params": {
    "left_models": ["kuayue:door/sliding_door_25t_bottom", "kuayue:door/sliding_door_25t_upper"],
    "right_models": ["kuayue:door/sliding_door_25t_bottom_lh", "kuayue:door/sliding_door_25t_upper_lh"],
    "is_slide_door": true
  },
  "registry_group": "kuayue:c25t_panels"
}
```

## 完整示例

以一个简单的车型为例，共三个文件。

**索引** `data/kuayue/kasuga_lib/data_driven/mymod.json`：

```json
{
  "on_register": [
    "carriages/mymod/groups.json",
    "carriages/mymod/blocks.json"
  ]
}
```

**内容** `data/kuayue/carriages/mymod/groups.json`：

```json
{
  "registry_groups": [
    {
      "id": "kuayue:mymod_panels",
      "properties": { "no_occlusion": true, "strength": [2.0, 4.0], "map_color": "gray" },
      "item_properties": { "tab": "kuayue:train_panel_tab" }
    }
  ]
}
```

**内容** `data/kuayue/carriages/mymod/blocks.json`：

```json
{
  "blocks": [
    { "id": "kuayue:mymod_bottom", "type": "train_panel", "registry_group": "kuayue:mymod_panels" },
    { "id": "kuayue:mymod_top", "type": "train_panel", "registry_group": "kuayue:mymod_panels" },
    { "id": "kuayue:mymod_floor", "type": "slab", "registry_group": "kuayue:mymod_panels" },
    {
      "id": "kuayue:mymod_end_face",
      "type": "custom_rendered_end_face",
      "params": {
        "door_type": "no_door",
        "frame_model": "carriage/mymod/mymod_end_face"
      },
      "registry_group": "kuayue:mymod_panels"
    }
  ]
}
```

## 重要注意事项

1. **方块 ID 格式：** 必须以 `kuayue:` 开头，后面跟英文小写和下划线。
2. **模型路径：** 如 `carriage/carriage25t/end_face/xxx`，是相对于 `assets/kuayue/models/` 的路径，**不**加 `kuayue:` 前缀（与方块 ID 不同）。
3. **每个方块都需要注册：** 即使方块只是模型不同、逻辑完全一样，也需要写一条独立的 `blocks` 条目（不同的 `id`）。
4. **文件放置位置：** 索引文件放 `.../data/kuayue/kasuga_lib/data_driven/`，内容文件放 `.../data/kuayue/carriages/<名称>/`——两者都在**车型模块目录**（`resources/<类别>/<车型>/`）下，且该目录必须有 `module.toml` 才会被编译识别。文件名任意。
5. **不需要写 Java 代码：** 方块注册后自动获得方块物品和创造模式标签页。无需编写 `@Context` 类或调用 `REGISTRY.register()`。

## 调试方法

启动游戏后，检查 `run/logs/debug.log`，搜索以下关键字确认注册结果：

- `Loaded N JSON entries across M types for mod 'kuayue'` — 成功读取并解析 JSON（N = 分组 + 方块总数）
- `Posting deferred registry entry` — 每个方块注册时打印一次
- `Source file not found for mod 'kuayue': data/kuayue/...` — 索引里列出的内容文件路径不对
- `Index file '...' for mod 'kuayue' contains unsupported field '...'; an index file may only contain 'on_register' and 'on_reload'` — 索引文件里写了 `on_register`/`on_reload` 之外的顶层字段（比如把方块定义直接写进了索引；沿用旧字段名 `sources` 也会触发这一条）
- `Index file '...' for mod 'kuayue' declares neither 'on_register' nor 'on_reload'; an index file must declare at least one of them` — 索引文件两个字段都没写成数组（只写旧的 `sources` 等于什么都没写，会同时触发上一条与这一条）
- `Data-driven index for mod 'kuayue' declares neither 'on_register' nor 'on_reload' in any index file; no entries can be loaded` — 整个 mod 没有任何索引声明字段；跑到这一步就是零注册，上面的逐文件报错之后还会多这一条汇总

如果方块没有出现，按顺序排查：① 索引文件是否在 `data/kuayue/kasuga_lib/data_driven/`；② `on_register` 里列出的路径是否正确（相对 `data/kuayue/`、带 `.json` 后缀）；③ 内容文件是否在当前车型模块的 `data/kuayue/carriages/<名称>/` 下。
