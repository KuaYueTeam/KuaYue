# KuaYue 转向架数据驱动 Schema 设计

状态：第一阶段已实现
基线：轨道数据驱动提交 `ea34965` 之后的 `dev/data-driven` 分支

## 第一阶段范围

第一阶段已经移除 `AllCarriageBogeys` 和 `AllLocoBogeys` 中的注册表，将以下内容迁入
KasugaLibNext 注册期数据：

| 内容 | 数量 | 当前载体 |
|---|---:|---|
| BogeySize | 53 | `bogey_sizes` |
| BogeyBlock | 53 | `bogey_blocks` |
| BogeyStyle | 7 | `bogey_styles` |
| Style variant | 53 | `bogey_styles[].variants` |
| 共享方块实体 | 1 | `kuayue:loco_bogey_entity` |

本阶段保留 `KuaYueBogeyModels` 和 `KuaYueBogeyMotion` 作为 Java visual bridge。
OBJ 模型、部件变换、车轮和连杆运动尚未迁入 JSON，也不接 FSM。

## Registry groups

`groups.json` 定义三个注册组：

| ID | 父组 | 用途 |
|---|---|---|
| `kuayue:bogey_data` | 根组 | 通用父组 |
| `kuayue:carriage_bogeys` | `kuayue:bogey_data` | 车厢转向架 |
| `kuayue:loco_bogeys` | `kuayue:bogey_data` | 机车转向架 |

车厢组沿用旧值 `no_occlusion=true`、`strength=[1.5,3.0]`、
`requires_correct_tool=true` 和 `netherite_block=true`。机车组仅把强度改为
`[2.0,3.0]`。

`netherite_block` 是 KuaYue 注册的 `JsonPropertyParser` 扩展。值为 `true` 时把方块音效设为
`SoundType.NETHERITE_BLOCK`。

## Schema: bogey_sizes

```json
{
  "bogey_sizes": [
    {
      "id": "kuayue:pk209p",
      "wheel_radius": 0.4575
    }
  ]
}
```

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | 是 | 唯一 ResourceLocation |
| `wheel_radius` | 是 | 有限且大于 0 |

53 个旧 size ID 保持不变。当前全部轮径均为 `0.4575`。

## Schema: bogey_blocks

```json
{
  "bogey_blocks": [
    {
      "id": "kuayue:pk209p_bogey",
      "size": "kuayue:pk209p",
      "registry_group": "kuayue:carriage_bogeys",
      "default_style": "kuayue:carriage",
      "physics": {
        "primary_track_type": "standard",
        "valid_track_types": ["standard"],
        "wheel_point_spacing": 2.5,
        "connector_anchor_offset": [0.0, 0.21875, 1.0],
        "allow_single_bogey_carriage": true
      }
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 保持旧 BogeyBlock ID |
| `size` | 是 | 引用 `bogey_sizes` |
| `registry_group` | 否 | 省略时挂到根组 |
| `default_style` | 是 | 引用 `bogey_styles` |
| `properties` | 否 | block property 覆盖 |
| `physics` | 是 | Create 运行参数 |

`physics`：

| 字段 | 必填 | 默认 |
|---|---|---|
| `primary_track_type` | 否 | `standard` |
| `valid_track_types` | 否 | `[primary_track_type]` |
| `wheel_point_spacing` | 是 | 无 |
| `connector_anchor_offset` | 否 | `[0.0, 0.21875, 1.0]` |
| `allow_single_bogey_carriage` | 否 | `false` |

当前数据中，车厢 block 使用 2.0 或 2.5 的轮点间距并允许单转向架车厢；机车 block
统一使用 2.0，且不允许单转向架车厢。

block 创建阶段 style 尚未 commit，因此 `default_style` 保存为 ResourceLocation，
通过 supplier 延迟查询 `AllBogeyStyles.BOGEY_STYLES`。

## Schema: bogey_styles

```json
{
  "bogey_styles": [
    {
      "id": "kuayue:carriage",
      "cycle_group": "kuayue:kuayue_bogey",
      "registry_group": "kuayue:bogey_data",
      "translation_key": "kuayue.bogey.style.carriage",
      "variants": [
        {
          "size": "kuayue:pk209p",
          "block": "kuayue:pk209p_bogey",
          "visual": "kuayue:legacy/pk209p_forward"
        }
      ]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | Create BogeyStyle ID |
| `cycle_group` | 是 | Create style 循环组 |
| `registry_group` | 否 | style 注册组 |
| `translation_key` | 是 | 本地化展示名 |
| `variants` | 是 | 至少一个 variant |

variant：

| 字段 | 必填 | 说明 |
|---|---|---|
| `size` | 是 | 引用 size，且必须等于 block 的 size |
| `block` | 是 | 引用 block |
| `visual` | 是 | 第一阶段 Java visual bridge ID |

7 个 style 的 variant 数分别为：

| Style | variant 数 |
|---|---:|
| `kuayue:carriage` | 8 |
| `kuayue:meter_carriage` | 5 |
| `kuayue:andesite_carriage` | 8 |
| `kuayue:loco` | 15 |
| `kuayue:asymmetry_loco` | 1 |
| `kuayue:meter_loco` | 4 |
| `kuayue:andesite_loco` | 12 |

## Java visual bridge

第一阶段约定 `visual` 使用：

```text
kuayue:legacy/<profile>
```

`LegacyBogeyVisuals` 维护 profile 到现有 `KuaYueBogeyModels` supplier 的显式映射。
JSON 只选择视觉 profile，不描述 OBJ、part、局部 transform 或 motion。

style commit 后执行：

```text
style + size + LegacyBogeyVisuals profile
    -> KuaYueBogeyModels.register(...)
```

未知 profile 会在注册期失败，而不是等到客户端渲染时静默缺模型。

## Renderer 与 block entity

`KuaYueBogeyRenderers` 从静态 Java 列表改为按 size ID 注册的 binding 表：

- data handler 在 style variant 处理时调用 `bind(sizeId, sizeReg)`；
- client sink 已安装时立即注册；
- sink 晚于 binding 安装时，安装过程会补注册已有 binding；
- renderer handle 仍为 `kuayue:proxy/<size>`。

共享 `kuayue:loco_bogey_entity` 不再手写 53 个 supplier。数据 handler 收集全部
`BogeyBlockReg`，style phase 创建 block entity 时统一传入 valid block supplier 列表。

## 注册顺序

| phase | 类型 | 产物 |
|---:|---|---|
| 0 | `registry_groups` | 三个注册组 |
| 10 | `bogey_sizes` | `BogeySizeReg` |
| 40 | `bogey_blocks` | `BogeyBlockReg<CommonBogeyBlock>` |
| 50 | `bogey_styles` | `BogeyGroupReg`、renderer binding、visual bridge、共享 BE |

跨 handler 数据通过 `BuildContext.putMeta(...)` 传递：

- size ID -> `BogeySizeReg`
- block ID -> `BogeyBlockReg`
- block ID -> `BogeyBlockDefinition`
- 全部 data-driven block registrations
- style ID -> `BogeyGroupReg`
- style ID -> `BogeyStyleDefinition`

## 校验规则

`BogeyDefinitionParser` 在纯 JVM 阶段校验：

- 顶层和各级对象拒绝未知字段；
- size、block、style ID 唯一；
- block 的 size 和 default style 存在；
- style 内不得重复 size；
- variant 的 size 和 block 存在；
- variant size 与 block size 一致；
- block 的 default style 与包含它的 style 一致；
- 每个 block 恰好出现在一个 style variant 中；
- 每个 block 都有对应 blockstate 资源；
- 53 个 block 全部进入共享 block entity。

## 尚未数据化的内容

第二阶段需要迁移：

- `bogey_models`：OBJ 引用、part ID、有序 transform；
- `bogey_motions`：`wheel_spin`、`rod_rotation` 和 QJ 专用 motion factory；
- style variant 从 `visual` 切换到 `model`；
- `KuaYueBogeyModels` 中按 size/profile 分支的 Java 表；
- `KuaYueBogeyMotion` 中按 size path 和 model path 分支的运动选择。

第三阶段再评估 `state_machines` / `animation_clips`。连续车轮角度和传动杆运动继续使用
`ModelPart.Motion`；FSM 只用于刹车、悬挂等离散或需要跨帧保持的状态。

## 后续 schema 方向

建议继续拆成两个注册期 schema：

```text
bogey_models
bogey_motions
```

`bogey_models` 负责几何和有序局部 transform，`bogey_motions` 负责可复用运动 profile。
style variant 最终引用 `model`。这样前后向和 Andesite 变体可以共享几何数据，同时保留各自
的 transform 和 motion 参数。

不建议把模型、motion、style 和 block 重新合并成一个巨大的 `bogeys` 文档。当前按职责拆分的
数据入口更容易做跨引用校验，也能让注册期和 reload 期保持清晰边界。
