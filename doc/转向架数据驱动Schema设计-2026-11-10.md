```text
modules/train-parts/resources/bogeys/data-driven/

    └── bogeys/

```

索引：

```json
{
  "on_register": [
    "bogeys/groups.json",
    "bogeys/bogeys.json",
    "bogeys/motions.json",
    "bogeys/models.json"
  ],
  "on_reload": [
    "animation_clips/qj_mechanism.json"
  ]
}
```

`module.toml` 是资源编译器识别模块根的标记。缺少它时，以上文件不会进入 jar。
QJ 剪辑通过 `on_reload` 注册到 KasugaLibNext 的 animation clip 注册表；motion 在绑定
QJ part 时按 clip ID 解析已注册的 `AnimationClip`。

## Registry groups

`groups.json` 定义：

| ID | 父组 | 用途 |
|---|---|---|
| `kuayue:bogey_data` | 根组 | 通用父组 |
| `kuayue:carriage_bogeys` | `kuayue:bogey_data` | 车厢转向架 |
| `kuayue:loco_bogeys` | `kuayue:bogey_data` | 机车转向架 |

车厢组使用 `strength=[1.5,3.0]`，机车组使用 `[2.0,3.0]`。两组都启用
`no_occlusion`、`requires_correct_tool` 和 `netherite_block`。

`netherite_block` 是 KuaYue 注册的 block property 扩展，映射到
`SoundType.NETHERITE_BLOCK`。

## Schema: bogey_sizes

```json
{
  "bogey_sizes": [
    {
      "id": "kuayue:pk209p",
      "wheel_radius": 0.4575
    }
  ]
}
```

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | 是 | 唯一 ResourceLocation |
| `wheel_radius` | 是 | 有限且大于 0 |

size 描述 Create 物理尺寸。它与 block 分开，因为同一个物理尺寸可以由多个 block、style
或注册组复用。

## Schema: bogey_motions

```json
{
  "bogey_motions": [
    {
      "id": "kuayue:motion/wheel_spin/scale_3.256_sign_-1",
      "type": "wheel_spin",
      "scale": 3.256,
      "sign": -1
    },
    {
      "id": "kuayue:motion/qj/formula",
      "type": "formula",
      "clip": "kuayue:qj_mechanism"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一 motion ResourceLocation |
| `type` | 是 | `wheel_spin`、`rod_rotation` 或 `formula` |
| `scale` | 否 | 默认 1，必须有限且大于 0 |
| `sign` | 否 | 默认 1，必须有限且非 0 |
| `clip` | `formula` 必填 | 引用已注册的公式动画剪辑 |

当前 motion 分布：

| type | 数量 | 行为 |
|---|---:|---|
| `wheel_spin` | 7 | 车轮角度与齿轮比 |
| `rod_rotation` | 1 | DFH21 传动杆 Z 轴旋转 |
| `formula` | 1 | QJ 左右连杆、曲柄、十字头和偏心杆，共 12 个 target |

`wheel_spin` 使用 `ModelPart.Spin`：

- placed block entity 使用 tick domain；
- train contraption 使用 frame domain。

`rod_rotation` 和 `formula` 使用完整 `TransformMotion`，分别构造 tick/frame supplier。
`formula` 在绑定阶段通过 clip ID 解析共享 sampler。每个 QJ part 的 motion callback 写入
`query.wheel_angle` 后采样自己的 part target；sampler 对同一输入的重复采样复用缓存。

## Schema: QJ formula animation clip

`qj_mechanism.json` 包含一个 `kuayue:qj_mechanism` clip。变量段保存轮角换算、四连杆几何和
12 个目标所需的中间量，`formula_transforms` 保存 part target 与最终 transform：

```json
{
  "animation_clips": [
    {
      "id": "kuayue:qj_mechanism",
      "duration_seconds": 1.0,
      "variables": [
        {
          "name": "qj.angle",
          "expression": "rad(qj.degrees)"
        }
      ],
      "formula_transforms": [
        {
          "target": { "part": "part_06" },
          "transform": {
            "translate": { "z": "0.1 + qj.crank_x" },
            "rotate": { "x": "-qj.crank_rotation", "y": "180" }
          }
        }
      ]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `target.part` | part target 必填 | 整个刚体 part ID |
| `target.bone` | 可选 | part 实例内骨骼；只有 `bone` 时用于单实例模型 |
| `transform.translate` | 否 | `x`、`y`、`z` 表达式 |
| `transform.rotate` | 否 | 欧拉角表达式，单位为度，组合顺序为 Z→Y→X |
| `transform.scale` | 否 | `x`、`y`、`z` 表达式，默认 1 |

`query.wheel_angle` 是宿主输入。QJ 先将其 wrap 到 `[0, 360)`，再由同一剪辑中的表达式生成
全部 transform。`FormulaTransformSampler` 的时钟不参与采样，剪辑只在 query 变化或显式
invalidate 后重新计算。

运行时链路：

```text
host wheel angle
    -> query.wheel_angle
    -> FormulaTransformSampler
    -> qj_mechanism variables / formula_transforms
    -> ModelPart frame/tick formula motion
    -> model part
```

## Schema: bogey_models

```json
{
  "bogey_models": [
    {
      "id": "kuayue:bogey/cw2",
      "y_offset": -1.5078125,
      "parts": [
        {
          "id": "part_00",
          "model": "kuayue:models/block/bogey/cw2/bogey_cw2_temple.obj",
          "local": [
            {
              "scale": [0.998046875, 0.998046875, 0.998046875]
            }
          ]
        },
        {
          "id": "part_01",
          "model": "kuayue:models/block/bogey/915mm_carriage_general_wheel.obj",
          "local": [
            {
              "translate": [0, 0.805, -1.18]
            }
          ],
          "motion": "kuayue:motion/wheel_spin/scale_1.0_sign_1"
        }
      ]
    }
  ]
}
```

model：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一 model ResourceLocation |
| `y_offset` | 否 | 默认 `-1.5078125` |
| `parts` | 是 | 至少一个 part |

part：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | model 内唯一 |
| `model` | 是 | OBJ/模型 ResourceLocation |
| `local` | 否 | 有序 transform operation |
| `motion` | 否 | 引用 `bogey_motions` |

`local` 中每个 operation 必须且只能包含：

```json
{"translate": [x, y, z]}
{"rotate": [x, y, z]}
{"scale": [x, y, z]}
```

数组顺序就是 `Transform` 的执行顺序。当前数据保留旧 renderer 的以下顺序：

1. 可选的 Y 轴 180 度翻转；
2. 可选的 Andesite X 轴 1.2 倍缩放；
3. 平移；
4. 可选的 Y 轴局部旋转；
5. 可选的 X 轴局部旋转；
6. 可选的模型整体缩放。

## Schema: bogey_styles

```json
{
  "bogey_styles": [
    {
      "id": "kuayue:carriage",
      "cycle_group": "kuayue:kuayue_bogey",
      "registry_group": "kuayue:bogey_data",
      "translation_key": "kuayue.bogey.style.carriage",
      "variants": [
        {
          "size": "kuayue:pk209p",
          "block": "kuayue:pk209p_bogey",
          "model": "kuayue:bogey/pk209p"
        }
      ]
    }
  ]
}
```

variant：

| 字段 | 必填 | 说明 |
|---|---|---|
| `size` | 是 | 引用 size，且等于 block 的 size |
| `block` | 是 | 引用 block |
| `model` | 是 | 引用 `bogey_models` |

style commit 后：

```text
style + size + BogeyModelPlan
    -> KuaYueBogeyModels.register(...)
    -> BogeyModels placement
    -> compiled plan registry
```

placed proxy 与 contraption proxy 都用 `(style, size)` 查询 `BogeyModelPlan`，再绑定当前
host 的 wheel angle。旧版按 size path 和 OBJ path 猜测车轮、传动杆、QJ 运动的分支已删除。

placed block 的 root 在应用 model 的 `local` 和 motion 前，会绕自身 Y 轴旋转 180 度。
该转换只修正 block host 与数据模型前向轴之间的差异；train contraption 继续直接使用
Create 提供的组装坐标系。

## Renderer 与 block entity

`KuaYueBogeyRenderers` 使用按 size ID 注册的 binding 表：

- style handler 处理 variant 时调用 `bind(sizeId, sizeReg)`；
- client sink 已安装时立即注册；
- sink 晚于 binding 安装时补注册已有 binding；
- renderer handle 为 `kuayue:proxy/<size>`。

共享 `kuayue:loco_bogey_entity` 收集全部 data-driven `BogeyBlockReg`，不再手写 53 个
valid-block supplier。

## 校验规则

`BogeyDefinitionParser` 校验：

- 各文档和嵌套对象拒绝未知字段；
- size、motion、model、block、style ID 唯一；
- model part ID 在 model 内唯一；
- motion type、scale、sign 和 formula clip 引用合法；
- local operation 类型和三维数组合法；
- model 的 motion 引用存在；
- style 的 model 引用存在；
- block 的 size 和 default style 引用存在；
- style variant 的 size、block、model 交叉引用一致；
- 每个 block 恰好出现在一个 style variant；
- 每个 block 有对应 blockstate；
- 53 个 block 全部进入共享 block entity。
